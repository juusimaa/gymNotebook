# Project working guidelines

- The default branch is `main`. Perform project work on a separate Git branch; do not work directly on `main`.
- Before writing or modifying project files, present a concise implementation plan to the user.
- Document the code clearly because this is also an educational project. Add useful comments or documentation that explain intent, behavior, and non-obvious decisions.
- Split large milestones into multiple focused, reviewable pull requests.
- When the work is complete and verified, ask the user for approval before creating a pull request.
