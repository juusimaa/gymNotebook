## Other paths and exclusions

- **Google Fonts:** removed by self-hosting in T001/PR #48; `frontend/index.html` and `frontend/src/styles/tokens.css` use local font files. T001 records a browser-network check. Google is therefore removed from the current recipient list; repeat the browser request check before publication if the frontend changes.
- **GitHub/GHCR:** holds source, build artifacts and CI logs. The repository is designed to use synthetic/test database data, not production account or rights-request records. Verify CI logs and any support issues before treating this as a permanent exclusion. Do not post personal requests or evidence here.
- **The user's device:** the browser stores a JWT in `localStorage`; a downloaded export is user-controlled after delivery. Neither is a supplier receiving a service-side copy. Browser storage and disposal appear in [retention.md](retention.md).
- **Operator's restricted local register:** Q8 places only minimal request metadata on a FileVault-encrypted local device with cloud sync disabled. No new hosted register supplier is introduced. Verify backup/sync settings before the first request.
- **Other support recipients/CDNs:** none identified from the current source and network path. This is a discovery result, not a guarantee about unreviewed provider support tickets, diagnostics or future integrations. Any support disclosure of user material must be inventoried before it occurs.

## Review trigger and evidence to collect

### T076 read-only checks, 2026-09-29

- **Neon project access:** the production project had one organization member and one project member, both the signed-in operator with admin role. The API listed no pending organization invitations and no personal or organization API keys. The sole `main` branch was not marked protected. These checks support the current customer-side branch/restore access restriction; they do not cover database credentials, provider personnel, recovery access or every authentication path. Recheck before release and after any membership/key change.
- **Neon recovery:** the project still reported `history_retention_seconds: 21600`, one branch and zero snapshots. This is configuration evidence only. An older-than-window restore rejection, provider internal copy expiry and deletion assistance are still unobserved.
- **Neon public terms:** the [2026-08-05 product schedule](https://neon.com/platform-terms) says Databricks personnel can access customer data via controlled, logged requests and describes backups. Its [subprocessor list](https://www.databricks.com/legal/databricks-subprocessors) names AWS among cloud providers and affiliates/support providers in several countries; the schedule adds Grafana Labs in the US. This is public, service-wide evidence, not proof of which paths receive this project's data or which DPA applies to this account. The [DPA page](https://www.databricks.com/legal/databricks-data-processing-addendum) offers an electronic signing process; no executed copy was reviewed.
- **Azure log routing:** `appLogsConfiguration.destination` for `cae-gymnote-prod-58dd` was `log-analytics` and its customer ID matched `log-gymnote-prod-58dd`. `az monitor diagnostic-settings list` returned empty lists for the two Container Apps, their managed environment and that workspace; the subscription Activity Log diagnostic-settings list was also empty. This rules out configured diagnostic exports on these inspected scopes at inspection time; it does not inventory provider-internal copies or other resources. The 90-day `AzureActivity`/`Usage` table exception still needs content and expiry review.
- **Azure workspace access:** inherited RBAC showed one user with subscription `Owner` and the `gymnotebook-production-deploy` service principal with resource-group `Contributor`. The service principal has a GitHub Actions OIDC credential scoped to this repository's `production` environment, matching [the deployment workflow](../../.github/workflows/deploy.yml). Under [Microsoft's Log Analytics access rules](https://learn.microsoft.com/en-us/azure/azure-monitor/logs/manage-access), a Contributor role can read workspace logs. Thus log access is not literally limited to the human operator; deployment automation also has it. GitHub environment protection, provider staff access and other routes were not assessed. Review whether this access is acceptable for P4 before sign-off.
